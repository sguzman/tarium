# Project ontology

This directory belongs **inside each independent project**. Describe the project's complete domain ontology here so the project can be understood without private context or services.

Document stable concept IDs, definitions, attributes, relation types, constraints, terminology, source provenance, versioning, compatibility, and extension policy. Keep human-readable descriptions consistent with `ontology.json` and the actual implementation.

The starter JSON is intentionally empty: fill it with verified, publicly releasable domain material. Do not paste private notes, conversation fragments, proprietary source data, or unresolved provenance. When using public external ontologies, cite and license them clearly.

A project may add more specialized and locally checked formats, schemas, diagrams, examples, and validation tooling. It must not outsource its essential ontology to a private repository or unpublished parent.
